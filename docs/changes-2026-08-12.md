# Changes made on 12 August 2026

A log of one working session on branch `thci-003`. Times are IST. Everything below
was verified by rendering the affected pages and exercising the controllers
against the local database, usually inside a rolled-back transaction so no test
data was left behind.

---

## 1. Printed document pipeline

The invoice and quotation print views had drifted into two separate
implementations. They now render through one pipeline.

- `App\Support\Documents\DocumentData` is the single, template-agnostic view of
  an invoice or a quotation. A template never touches an Eloquent model, so the
  two documents cannot drift apart in what they show.
- `App\Services\DocumentRenderer` renders that data to the browser print view or
  to Dompdf, from the same Blade template (`resources/views/documents/templates/classic`).
- The old `invoices/print.blade.php` and `quotations/print.blade.php` were deleted.

### Header and identity

- Removed the company custom fields (the LUT registrations) from the document
  header. The LUT selected on a document already prints in the details table.
- When a company logo is uploaded it is the only mark shown; the text company
  name is now the fallback for companies without a logo, in the same style.

### Content decisions

- Removed the rate-wise CGST/SGST/IGST summary table. The per-line GST column and
  the totals block already carry the tax.
- Removed the signatory block. The running footer now reads "This is a computer
  generated document and does not require a signature."
- Invoice notes no longer print. They are internal (see section 3).
- Terms and bank details are now composed from company-level and document-level
  values (see section 4).

Files: `app/Support/Documents/DocumentData.php`, `app/Services/DocumentRenderer.php`,
`config/document-templates.php`, `resources/views/documents/`.

## 2. GST correctness

- **State codes.** `config/gst-states.php` was restructured into `states` plus
  `deprecated`. The list matches the CBIC codes. Three codes are hidden from new
  documents but still resolve on old ones: `25` (Daman and Diu, merged into `26`
  in January 2020), `28` (Andhra Pradesh before the split, now `37`), and `96`
  (Foreign Country, not a place of supply on a domestic invoice). `37` is now
  labelled plainly "Andhra Pradesh".
- **Place of supply** became a dropdown of all 41 states and UTs, on every form.
- **LUT number** became a dropdown of the company's LUT registrations, read from
  the company custom fields whose key contains "LUT" (`Company::lutOptions()`).
  A LUT saved on a document but no longer in settings stays selectable so editing
  cannot silently drop it.
- **`quotations.lut_number` did not exist.** The quotation forms collected a LUT
  and the controller never validated or stored it, so every export quotation lost
  it. Added the column, the validation, and the persistence.

## 3. Internal notes

- New `invoice_notes` table, `InvoiceNote` model, `InvoiceNoteController`, and
  `Invoice::privateNotes()`. Quotations already had an equivalent.
- Both documents now use one shared thread UI
  (`resources/views/documents/partials/notes-thread.blade.php`) instead of two
  different designs for the same feature.
- Notes can be deleted on both sides; previously only creation existed.
- The legacy single `invoices.notes` textarea was removed from the create and
  edit forms, and its content migrated into the thread as the first note.
- Fixed a crash: the quotation note card called `$note->user->name` directly,
  which fatals once the author's user record is deleted (`user_id` is
  `nullOnDelete`).

## 4. Terms and bank details, global and per document

- Company settings gained a global terms block.
- Every invoice and quotation carries a four-way switch on both terms and bank
  details: use the company value, use its own, print both, or print neither.
  In "both", the company block prints first, one blank line apart.
- Document-level bank details are label/value rows, so an export invoice can add
  SWIFT and IBAN on top of the domestic block. A row whose label matches a
  company one replaces it.
- One shared form partial for all four forms
  (`documents/partials/presentation-fields.blade.php`).

## 5. Invoice workflow

- **Approved state.** `invoices.status` gained `approved`, with `approved_at` and
  `approved_by`. Approving requires a note, enforced server-side, and the note is
  filed both in the private thread and on the approval revision.
- **Payments are gated.** A payment can only be recorded between approval and
  full settlement. A settled invoice is closed to further changes.
- **Part payments and revisions.** New `invoice_revisions` table. A revision is
  written on approval and on every payment, each holding the total, the amount
  received to date, and the balance. The Revisions tab renders that as a timeline.
- **Status without editing.** Status was removed from both edit forms and is now
  a one-click menu on the record page, with rules enforced in the controller:
  `approved` only through the approve action because it needs a note, `paid` only
  through the payments ledger, nothing at all once settled.

## 6. Document numbering

Replaced `INV-` plus eight random characters with a company-defined format.

- `App\Services\DocumentNumberGenerator` renders a format such as
  `INV-{CLIENT}-{YYYY}-{MM}-{SEQ:2}` into `INV-CLI1-2026-08-01`. Tokens: `FY`,
  `FY_SHORT`, `YYYY`, `YY`, `MM`, `DD`, `CLIENT`, `SEQ`, with friendly aliases
  (`{year}`, `{month}`, `{count}`, `{Client ID}`).
- The counter is scoped to everything in the number except the sequence, so the
  format itself decides the reset: `{FY}` restarts each April, `{CLIENT}` counts
  per client. Counters live in `document_sequences` and increment under a row
  lock, so two documents created at the same moment cannot collide.
- Validated against rule 46 of the CGST Rules: at most 16 characters, and only
  letters, digits, hyphen and slash. A bad format is rejected on save with the
  reason.
- Clients gained a `code` column, with a `CLI{id}` fallback, so `{CLIENT}` works.
- Applies to quotations too, with its own format field.

## 7. Quotation to invoice

- The clone action is now prominent in the quotation header when the quotation is
  approved and not yet cloned, and becomes a link to the invoice afterwards.
- The clone previously dropped the LUT and the custom fields; it now carries
  those, plus the terms and bank choices.
- `Invoice::quotation()` gives the reverse link, shown on the invoice's Revisions

- The quotation list flags every approved quotation with either its invoice number
  or an amber "Invoice pending" badge.
- The cloned invoice was still getting a random number; it now uses the company
  numbering format.

## 8. Multiple bank accounts

- Settings → Bank Details is now an account manager.

## 9. Interface

### App shell

- Replaced the Breeze top navigation with a fixed 256px sidebar: grouped
  navigation, a primary-washed active state, the account menu docked at the
  bottom, and an off-canvas drawer on mobile.
- Sticky topbar with breadcrumbs and the create actions.
- The old `layouts/navigation.blade.php` was deleted.

### Design tokens

- `resources/css/app.css` now declares the shadcn token contract as HSL triplets
  (`--background`, `--foreground`, `--muted`, `--border`, `--ring`, `--radius`,
  plus state and sidebar tokens), consumed through `hsl(var(--token))` in
  `tailwind.config.js`. Dark values are defined but nothing toggles `.dark` yet.
- The canvas is tinted and surfaces are white, which is what makes the sidebar
  read as a column rather than as links on a page.

### Settings

- The single long company settings page became five addressable sections:
  Company Information, Bank Details, Terms & Conditions, Numbering, Custom Fields.
- Each section is a real URL and its own form, so deep links work, browser back
  works, validation errors return to the right section, and saving one section
  cannot rewrite another.
- `CompanyController` and `company/edit.blade.php` were removed in favour of
  `SettingsController`. `/company/settings` still redirects.

### Record pages

- The second-level left menu inside the invoice and quotation pages was removed.
  Both now have a record header (number, status, client, dates, actions), a
  four-across figures strip, and horizontal tabs.
- Tabs are real URLs (`?tab=payments`), so deep links and browser back work, and
  the note and approval forms return to the tab they came from.
- Content moved into section partials, several shared between the two documents.

### Auth

- Two-column sign-in and registration: a dark brand panel carrying the company
  logo over a ruled ledger grid drawn in CSS, and the form panel beside it.
- Page titles are dynamic, from `App\Support\Brand`: "Invoices · The Higglers
  Company" rather than "Laravel".

### Shared partials, to stop the drift

`documents/partials/`: `notes-thread`, `bank-panel`, `document-preview`,
`record-tabs`, `status-menu`, `supply-fields`, `presentation-fields`.

## 10. Bugs found and fixed

Ordered by severity.

1. **Internal notes leaked to clients.** The Private Notes and Revisions sections
   on the invoice page had no admin guard, so a client user viewing their own
   invoice could read the internal thread and the approval reasoning. Reproduced
   with a real client user before fixing. Now guarded in the view *and* in the
   controller, which no longer loads those relations for a client user at all.
2. **Editing an approved invoice silently un-approved it.** `update()` validated
   `status` as `in:draft,sent,paid,overdue` with `approved` missing, and the form
   offered no `approved` option, so the browser showed "Draft" and saving wrote
   `draft` while `approved_at` stayed set. Status left the edit form entirely.
3. **Every edit reset the terms and bank fields.** `documentPresentationRules()`
   was added to the store validation but not to update, so those fields fell back
   to defaults and overwrote what was stored.
4. **Tax rate reverted to 0% on edit.** The options used Alpine's `:value`
   binding; `x-model` runs before those bindings exist, so the select could not
   match its stored value and fell back to the first option. Static values now.
5. **Cloned invoices bypassed the numbering format**, getting a random number.
6. **Quotation delete was unreachable.** It was hidden whenever any version in the
   series was approved. The real constraint is being cloned to an invoice, so that
   is now the only block; deleting a root removes its revisions, items, and notes
   in one transaction instead of leaving orphans.
7. **`@php(...)` short form broke a page.** Blade's raw-block regex matched from
   the short-form directive to a later `@endphp`, swallowing everything between.
   Note that `php artisan view:cache` does not catch this: it compiles without
   linting. Compiled output is now linted with `php -l`.
8. **Revision timeline dots stacked.** They were `absolute` inside a positioned
   `<ol>` with unpositioned `<li>`s, so every dot anchored to the list.
9. **State dropdown never preselected.** PHP casts numeric array keys, so
   `config('gst-states')` returns `27` as an int and `'27' === 27` is false.
10. **Money was grouped two ways.** Screen used `number_format` (120,000.00) while
    the PDF used `Money::format` (1,20,000.00). Screen now matches the paper.
11. **A settled legacy invoice was offered approval**, and its payments panel read
    "approve this first" rather than "settled and closed".
12. **Removing the status field ate a closing `</div>`**, which pulled the items
    table inside the field grid on both edit forms. Fixed, and verified by
    comparing rendered nesting depth against the untouched create forms.
